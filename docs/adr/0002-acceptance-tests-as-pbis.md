# 受け入れテストは実装役の PBI として先に作り、鍵をかける

v8 はテスト役を置かないと決めた (docs/specs/atelier-v8.md)。一方で、作業者が自分でゴールを書いて自分で通す形では、テストを骨抜きにしても気づけない。そこで、新しい役は足さずに、承認したシナリオを受け入れの PBI として最初の wave で実装役に作らせ、Red の確認と planner の確認を通してから鍵をかける。以降の作業者は鍵のファイルを変えられず、違うと思えば異議を残して進む。

## Considered Options

- テスト役を足す (v7 の tester に近い形): 役・テンプレート・経路の検査がすべて増える。v8 で減らした起動と指示文が戻る。
- 作業者が受け入れテストも書く (今の v8 に近い形): 自分で採点することになり、ステップ定義の骨抜き・値の決め打ちを防げない。
- 受け入れの PBI として実装役に作らせる (採用): 役は増やさず、合否は進行役の検査 (Red の確認・鍵・流れたケースの数・控え) で決まる。モデルの判断が入るのは planner の確認 1 回だけ。
