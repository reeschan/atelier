# 優先テンプレート (テンプレートと適用) と Web 版

## Problem Statement

オーケストレーションの振り分け (どの PBI をどの実行先・モデル・effort で実装するか) を、期間を区切って変えたいことがある。例: 「来週の木曜 23:59 まで、実装はすべて DeepSeek 4.1 の effort MAX に回す」。

いまは、これをスキルの新しい版として作り、期限の日付をコードに埋めている。そのため次の問題がある。

- 延長・短縮・取りやめのたびに、新しい版を作って切り替える必要がある。
- 期限を過ぎると黙って元に戻り、続けたいかを聞かれる機会がない。
- 版の履歴に一時的な運用が混ざり、スキル本体の変更と見分けにくい。
- 今どの振り分けが効いているかを、手元の PC 以外 (スマホなど) から確かめたり変えたりできない。

## Solution

振り分けの上書きを、版とは別の「テンプレート」として名前付きで保存する。それを期限付きでオンにしたものを「適用」と呼び、同時に 1 つだけ持てる。

- テンプレートはチャットで作る。Claude が実在するモデル名・effort 名かを確かめてから保存する。
- 適用は、claude.ai の非公開の Web ページ (Artifact) から始める・延長する・止めることができる。チャットで頼んでもよい。
- オーケストレーションは開始時に Web の適用を読み、決定表のあとでテンプレートを当てる。承認一覧の表には、どのテンプレートで決まったかを出す。
- 期限が来た適用は、期限切れの扱いが `ask` なら自動では当てない。次の PBI の承認か Web の画面で、「延長 / やめる / 期限なし」を聞く。
- 毎朝、24 時間以内に期限が来る適用があれば通知する。
- sensitive な PBI を外部の実行先に出すこと、設計判断の見直しとレビューの担当は、テンプレートでは変えられない。

## User Stories

1. オーケストレーションの利用者として、振り分けの上書きに名前を付けて保存したい。同じ上書きを何度も使い回せるように。
2. 利用者として、テンプレートを期限付きで適用したい。期間限定の運用を、スキルの版を変えずに始められるように。
3. 利用者として、適用の期限を延長したい。版を作り直さずに期間だけを変えられるように。
4. 利用者として、適用を期限の前に止めたい。不調に気づいたらすぐ元の振り分けに戻せるように。
5. 利用者として、期限の無い適用を作りたい。気に入った振り分けを常用にできるように。
6. 利用者として、期限が切れた適用について、続けるかどうかを聞かれたい。意図せず元に戻ったり、意図せず続いたりしないように。
7. 利用者として、期限切れの扱いを「聞かずに外す」にもしたい。確認が要らない一時措置では手間を省けるように。
8. 利用者として、期限の前日に通知を受けたい。延長するかどうかを前もって決められるように。
9. 利用者として、スマホからでも今の適用を確かめたい。外出先でも、どの振り分けで動いているかが分かるように。
10. 利用者として、スマホからでも適用を始める・延長する・止めることをしたい。PC の前にいなくても運用を変えられるように。
11. 利用者として、Web の画面で期限切れの適用に答えたい。次にオーケストレーションを使うときに止まらずに済むように。
12. 利用者として、テンプレートの一覧と、それぞれが段ごとに route をどう変えるかを Web で見たい。適用する前に中身を確かめられるように。
13. 利用者として、過去の適用の履歴 (いつ・何を・どれくらい・どう終わったか) を見たい。どの運用がうまくいったかを振り返れるように。
14. 利用者として、チャットで「deepseek-all を 11/5 まで適用して」と頼みたい。Web を開かなくても運用を変えられるように。
15. 利用者として、チャットで「今の振り分けをテンプレートにして」と頼みたい。試した設定をそのまま残せるように。
16. 利用者として、テンプレートを当てる段 (haiku・sonnet・opus) を選びたい。軽い PBI だけ別の実行先に回す、といった使い分けができるように。
17. 利用者として、テンプレートで effort を指定したい (例: DeepSeek の max)。実行先の性能を引き出せるように。
18. 利用者として、テンプレートの実行先が使えないときも、PBI が止まらずに Claude で実装されてほしい。上限やエラーで作業が詰まらないように。
19. 利用者として、sensitive な PBI がテンプレートによって外部の実行先に出ないことを保証されたい。画面の操作 1 つで安全の決まりが崩れないように。
20. 利用者として、設計判断の見直しとレビューがテンプレートの影響を受けないでほしい。実装の担当を変えても品質の歯止めが残るように。
21. 利用者として、PBI の承認一覧で、どの PBI にどのテンプレートが当たったかを見たい。承認の前に振り分けの理由が分かるように。
22. 利用者として、1 回のオーケストレーションの途中で振り分けが変わらないでほしい。同じ作業の PBI の担当がばらつかないように。
23. 利用者として、Web と同期できないときも、前回の写しでオーケストレーションを続けたい。ネットワークやログインの問題で作業が止まらないように。
24. 利用者として、同期できずに写しを使ったときは、そのことを承認一覧で知りたい。古い設定で動いている可能性に気づけるように。
25. 利用者として、モデル名や effort 名を書き間違えたテンプレートが保存されないでほしい。実行時に初めて失敗することがないように。
26. 利用者として、テンプレートの仕組みを入れた版に移ったあとも、今の DeepSeek の一時措置 (10/22 23:59 まで) がそのまま続いてほしい。移行で運用が途切れないように。
27. 利用者として、同じ期限の通知を二重に受け取りたくない。通知が煩わしくならないように。
28. スキルを公開リポジトリから使うほかの人として、自分用の Web ページを自分の非公開の Artifact として発行したい。他人のデータと混ざらないように。
29. 公開リポジトリの利用者として、テンプレートの例を見て自分のテンプレートを作りたい。書き方が分かるように。
30. 利用者として、スキルの版を切り替えても、テンプレートと適用が消えないでほしい。版の切り替えと運用の設定を別々に扱えるように。

## Implementation Decisions

### 用語

- 用語集 (CONTEXT.md) の「テンプレート」「適用」「期限切れの扱い」「段」「route」「sensitive」に従う。「優先テンプレート」は画面上の言い方で、今の適用が指すテンプレートを指す。

### テンプレート

- テンプレートは、名前・説明と、段ごとの route の上書きを持つ。上書きを持たない段には当たらない。
- route の上書きの各手順は、実行先・モデル・effort を持つ。effort は、opencode では variant (モデル名の後ろの `#<effort>`) として渡す。
- 正本は、スキルのルート (版の外) にあるテンプレートの置き場所。版を切り替えても残る。
- テンプレートの作成・書き換えはチャットで行う。保存の前に、形の検査と、実行先で実在するモデル名・effort 名かの確認を Claude が行う。opencode では、存在しない variant が `provider.no-route` で拒否されることを利用できる。
- 保存したテンプレートは、Claude が Web のデータベースにも写す (閲覧用)。
- 公開リポジトリには、個人のテンプレートを入れず、例だけを置く。

### 適用

- 適用は、テンプレート名・期限 (日時とタイムゾーン、または期限なし)・期限切れの扱い (`ask` / `drop`)・理由・始めた日時と経路 (Web / チャット) を持つ。
- 同時に存在できる適用は 1 つだけ。新しく適用すると、前の適用は「置き換え」で終わり、履歴に残る。
- 適用の終わり方は、期限切れ (`drop`)・ユーザーが止めた・置き換え・期限切れ後に「やめる」と答えた、のどれか。履歴に記録する。
- 正本は Web ページのデータベース。チャットで適用を変えるときも、Claude がまずデータベースに書く。ローカルには写し (overrides) を置き、手で書き換えない。

### 同期

- オーケストレーターは、オーケストレーションの開始時 (PBI を分ける前) に 1 回だけ、ArtifactData で Web の適用を読む。読んだ内容を新しい小さなコマンドに渡し、ローカルの写しを書かせる。
- その作業の終わりまでは、開始時の判定を使う。途中で期限が来ても判定し直さない。
- 同期できないとき (ArtifactData が使えない、ページの URL が未設定など) は、前回の写しを使い、承認一覧に「Web と同期できず、◯日時点の写しを使用」と出す。
- Web ページの URL は、各利用者のスキル側 (版の外) に置く。

### 振り分け (`select_model.py`)

- 決定表で段を決めたあとに、適用中のテンプレートを当てる。
- 当てる条件: 適用があり、期限内 (または期限なし) で、その段の上書きがあり、PBI が sensitive でないこと。
- 当てたときの route は、テンプレートのその段の route のあとに、元の段の Claude (Agent) を最後の受け皿として付けたもの。Codex・Antigravity などの通常の route は通らない。
- `--skip` で外した実行先は、テンプレートの route からも外す。空になったら Claude だけになる。
- 期限切れで扱いが `ask` の適用は当てず、出力に「期限切れの確認が要る」ことを示す。`drop` は当てない。
- 出力 (1 件の JSON と、全件の表) に、当てたテンプレート名 (または当てなかった理由) を足す。適用が無いときの route は、今の版と同じ。
- 判定に使う「今」は、テストのために外から渡せるようにする (今の `--today` と同じ考え方。期限は時刻まで比べる)。
- テンプレートと適用の置き場所は、引数で差し替えられるようにする (テストのため)。省略時はスキルのルートを使う。

### 期限切れの確認

- 期限切れの `ask` の適用があるとき、オーケストレーターは PBI の承認 (もともと止まる場面) で「延長 (期限を聞く) / やめる / 期限なし」を一緒に聞く。新しい止まる場面は増やさない。
- 答えは Claude が Web のデータベースに書き、写しも更新してから、担当を判定し直す。

### Web ページ

- 非公開の Artifact として発行し、データベースの capability を使う。利用者本人だけが読み書きする。
- 表示: 今の適用 (テンプレート名・期限・残り時間・理由)、テンプレートの一覧と中身 (段ごとの route の変化)、適用の履歴。
- 操作: 適用を始める (テンプレート・期限・期限切れの扱い・理由を選ぶ)、延長する、止める、期限切れの適用に答える。テンプレートの作成・書き換えはできない。
- ページには個人のデータを埋め込まない。データはすべてデータベースから読む。ページのソースは公開リポジトリに置き、各利用者が自分の Artifact として発行する。

### 通知

- 毎朝 9:00 に 1 回動くスケジュールタスクを 1 つ置く。Web の適用を読み、24 時間以内に期限が来る適用があるときだけ通知する。該当がなければ何もせずに終える。
- タスクは読むだけで、適用を変えない。
- 個別の前日通知は予約しない。2026-10-16 に予約した 10/21 の通知は、毎朝のタスクに移したら消す。

### 版と移行

- テンプレートの仕組みを入れた版を v14 とする。v13 の、コードに埋めた期限 (全段を DeepSeek に回す一時措置) は消す。opencode に effort を渡す説明は残す。
- 今の一時措置を `deepseek-all` テンプレートに移す。内容は、haiku・sonnet・opus の全段の route を `opencode-go/deepseek-v4.1-flash` の effort max にするもの。
- 移行時に、期限 2026-10-22 23:59 (+09:00)・期限切れの扱い `ask` で適用しておく。v14 に切り替えた時点から同じ振り分けが続くようにする。
- 公開リポジトリにも同じ変更を反映する。テンプレートの例と Web ページのソースを含む。

## Testing Decisions

- よいテストは、外から見えるふるまい (コマンドの入力と出力) だけを確かめる。内部の関数の分け方には依存しない。
- 先例: 公開リポジトリの `select_model.py` のテスト。一時ディレクトリに facts と Jev の答えを書き、コマンドを別プロセスで起動して、出力の JSON の route を比べている。同じ形で足す。

### 合意済みの seam

1. **`select_model.py` のコマンド** (既存の境界)。入力は facts・Jev の答え・判定に使う「今」・テンプレートと適用の置き場所。出力は route の JSON と全件の表。確かめること:
   - 適用中のテンプレートが当たる
   - 上書きの無い段には当たらない
   - sensitive には当たらない
   - 期限切れで `ask` なら当てず、確認が要ると出す
   - 期限切れで `drop` なら当てない
   - 期限なしの適用は当たる
   - `--skip` でテンプレートの route が空になると Claude だけになる
   - 最後の受け皿は必ず元の段の Claude になる
   - 適用が無いときは今の版と同じ route になる
2. **テンプレートと適用を扱う新しいコマンド** (新しい境界)。Claude が Web のデータベースから読んだ内容を JSON ファイルで受け取る。確かめること:
   - ローカルの写しを書く
   - テンプレートの形を検査し、不正なものを拒む
   - 「24 時間以内に期限が来る適用」を出す
   - 期限切れの答え (延長 / やめる / 期限なし) を反映した適用と、履歴の 1 行を作る

### 自動テストにしないもの

- Web ページ: 発行後に、ArtifactData でデータベースを 1 回読む。表示と操作 (始める・延長・止める・期限切れへの答え) は、内蔵ブラウザで 1 回ずつ通して確かめる。
- 毎朝の通知タスク: 中の判定は seam 2 で確かめる。タスクそのものは 1 回手動で走らせて確かめる。
- ArtifactData とのやりとり: Claude のツールでしかできないため、Python のテストの外に置く。

## Out of Scope

- Web からテンプレートを作る・書き換えること (チャットで行う)。
- 複数の適用を同時に持つことと、その優先順位。
- sensitive の扱い、設計判断の見直し、レビューの担当をテンプレートで変えること。
- 1 回のオーケストレーションの途中 (波ごと) で適用を読み直すこと。
- Web に実行先ごとの利用統計を出すこと (あとで足せるようにはしておく)。
- 個別の適用ごとの前日通知の予約。
