# 作業者は自分の作業の検査だけを流し、全体の検査は進行役が 1 回だけ流す

合意: 2026-11-21、持ち主の決定。「PBI の作業が終わったら関連のテストを流すのは問題ない、全体は最後に 1 回」。

## Problem Statement

ある利用側のリポジトリで v8.6 の run を回したところ、作業者（外部 CLI、PBI ごとにまっさらな状態で起動）が PBI を終えたあと、計画の検査（型検査・単体テスト全部・lint 全体・未使用コードの検出・依存の向き）を全部流し、落ちると直して全部をもう一度流していた。

- 単体テストは約 1250 件で、1 回に 35〜70 秒かかる。1 つの PBI で単体テストを 3 回全部流した例があり、起動 1 回が 10 分の制限時間を超えた。
- 進行役も wave の終わりに同じ検査を全部流しているので、検査が二重になっている。
- 原因は 2 つ。作業者の指示が「`checks` のコマンドを全部流し、落ちたら直してまた全部流す（2 回まで）」になっていること。計画役が各 PBI の `checks` に全体の検査のコマンドを入れること。修正の段の作業者のチケットにも、計画の検査（全体）がそのまま入っていた。

## Solution

- 作業者は、作業をひととおり終えたら、その PBI に関係するテスト（例えば、その PBI の単体テストのファイルだけを `node --test <file>` で）と、変えたファイルの書式・lint だけを流す。落ちたら直してもう一度（2 回まで）。リポジトリ全体の検査は流さない。修正の段（mode `fix`）の作業者も同じ。
- リポジトリ全体の検査は、wave の終わりと修正の段の終わりに、進行役が 1 回だけ流す（今までどおり）。
- 計画役は、PBI ごとの `checks` に「その PBI に関係するテスト」だけを書き、全体の検査は計画の `checks` にだけ書く。

```
今:   作業者: 作る → 全体の検査を全部 → 落ちた → 直す → 全体をもう一度（2 回まで） → 進行役: 全体の検査
新:   作業者: 作る → 関係するテスト・変えたファイルの lint と書式 → 落ちたらそこだけ直して流し直す（2 回まで） → 進行役: 全体の検査（1 回）
```

## User Stories

1. As a 持ち主, I want 作業者が自分の PBI に関係するテストと、変えたファイルの lint・書式だけを流すこと, so that 起動 1 回が全体のテストの繰り返しで制限時間を超えない
2. As a 持ち主, I want 全体の検査が wave の終わりと修正の段の終わりに 1 回だけ流れること, so that 同じ検査を二重に払わない
3. As a 持ち主, I want 計画の PBI の検査に全体の検査のコマンドが入らないこと, so that 作業者に全体を流させる道が計画の側に残らない
4. As a 持ち主, I want 全体の検査で落ちたものを直す作業者（修正の PBI・E2E の直し）が、落ちた所だけを狭いコマンドで流して確かめること, so that 直しの起動でも全体を繰り返さない

## Implementation Decisions

- **作業者の指示（`prompts/worker.md`）**: 流すのは、変えたファイルだけへの lint・書式と、チケットの `checks`。チケットの `repository_checks`（全体の検査）と、ほかのリポジトリ全体のコマンドは流さない。直す失敗がチケットにあるとき（修正の PBI の `carry_over`、E2E の直しの `failure`）は、出力に出ている落ちたテストのファイルや spec だけを流す、いちばん狭いコマンドで再現して確かめる。直すのは今までどおり 2 回まで。
- **チケット（`atelier/actions.py`）**: 作業者のチケットの `checks` から、計画の `checks` に入っているコマンドを除く（`worker_checks`）。計画役が PBI の検査に全体のコマンドを入れてしまっても、作業者には渡らない。チケットに `repository_checks` を足し、進行役があとで流す全体の検査を作業者に見せる。
  - PBI を作るとき: `checks` は PBI の検査から計画の検査を除いたもの。`repository_checks` は計画の検査。
  - 修正の段のまとまり: `checks` は、直すファイルを `targets` に持つ PBI の検査（`plan.related_commands`）から計画の検査を除いたもの。前は計画の検査も入っていた。`repository_checks` は修正の段の検査と E2E。
  - E2E の直し（`FIX-E2E`）: `checks` は空。前は修正の段の検査と E2E を全部入れていた。落ちた所は `failure` から作業者が狭いコマンドで再現する。`repository_checks` は修正の段の検査と E2E。
  - 修正の PBI: 落ちたコマンドが全体の検査なら `checks` は空になり、`carry_over.failed_commands` と `output` から再現する。
- **進行役が流す検査は変えない**: wave の検査は「その wave の PBI の検査＋計画の検査」、修正の段の検査は「直すファイルの PBI の検査＋計画の検査」を、それぞれ 1 回流す。落ちたときの PBI への割り当て（計画の検査が落ちたらその wave の PBI に、修正の PBI を除いて割り当てる）も今のまま。
- **計画役の指示（`prompts/planner.md`）**: PBI の `checks` は、その PBI のファイルに絞った関係するテストだけ（例えば `node --test test/box.test.js`）。全体の単体テスト・型検査・リポジトリ全体の lint・未使用コード・依存の向きは計画の `checks` にだけ書く。関係するテストが無い PBI は `checks` を `[]` にする。
- **計画の検証（`atelier/plan.py`）**: PBI の `checks` の空を許す（前は 1 件以上を求めていたので、関係するテストが無い PBI に全体のコマンドを書かせる元になっていた）。ただし計画の `checks` も空なら、検査が 1 つも流れないので止める。
- **調べる役の指示（`prompts/surveyor.md`）**: 単体テストと E2E のコマンドには、1 ファイル・1 spec だけを流す方法がリポジトリにあれば `text` に書く。計画役が狭いコマンドを作る材料にする。
- 型検査のように全体でしか流せない検査は、作業者は流さず、wave の終わりの検査に任せる。そこで落ちたら、今までどおり持ち越しとして修正の PBI か修正の段で直す（`docs/specs/carry-over-failures.md`）。

## Testing Decisions

- `tests/test_worker_checks.py`: 進行役のコマンドを通して、PBI を作る作業者・修正の段の作業者・E2E を直す作業者のチケットの `checks` と `repository_checks`、wave の検査と修正の段の検査のコマンドが 1 回ずつであること、全体の検査で落ちた修正の PBI のチケットを確かめる。`worker_checks`・`related_commands`・計画の検証と、3 つの指示の文言も確かめる。
- `tests/test_plan.py`: PBI の `checks` が空でも、計画の `checks` があれば通ることに期待を直した。

## Out of Scope

- 手元のスキル（`~/.claude/skills/atelier/versions/`）の書き換え。版はマージのあとに skill-versioning で作る。
- 作業者が型検査を変えたファイルにだけ流す仕組み（ツールによってできないため、wave の検査に任せる）。
