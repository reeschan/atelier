# 呼び出し側の会話を短く保つ: drive を裏で回し、run のあとで会話を引き継ぐ

合意: 2026-11-19。持ち主が 3 つの問いにすべて推奨どおりに答えた（切るのは聞いてから・切る場所は設計の Ready の後と run の後・裏で回すのは drive）。前提は Atelier v8（`docs/specs/atelier-v8.md`）。

## Problem Statement

設計から PR まで 1 つの会話で通すと、会話が長くなり、応答のたびにその全体を読み直す。ある長い会話では、応答 1 回あたり数十万トークンをキャッシュから読み直し、それが応答の回数だけ重なっていた。

Atelier の呼び出し側のループは、この 2 つの量（応答の回数と、1 回に読む会話の長さ）を両方ふくらませる。

1. **モデルの要らない手まで本体が回す。** `check` は、コマンドを流す・結果の JSON を書く・`done` を呼ぶ、の 3 手を本体が回す。外部の実行先の `launch` も、本体が `run` を呼んで待つ。PBI と検査の数だけ本体の応答が増え、検査の出力も会話に積もる。
2. **進み具合を見に行く。** 待つあいだに `status` や結果のファイルを読みに行くと、その分の応答が増える。
3. **run のあとも同じ会話で続ける。** 仕上げと PR に要るのは、ブランチ・仕様・報告の場所くらいなのに、長い run の会話を抱えたまま進む。

## Solution

- `conductor.py drive --root <作業ルート>` を足す。モデルの要らない手（`check`・外部の実行先の `launch`・`prepare`）を自分で続けて済ませ、呼び出し側の出番の手（`agent` の `launch`・`ask`・`review_skill`・`omm_scan`・`done`）で止まって、`{"drove": [...], "next": <手>}` を返す。
- `drive --done <launch_id>` は、先にサブエージェントの起動を `done` で閉じてから続ける。サブエージェントが終わったあとの 1 手と、そのあとのモデルの要らない手が 1 回の呼び出しに収まる。
- 呼び出し側は `drive` を裏で（Claude Code では Bash の `run_in_background`）回し、終わったという通知を待つ。待つあいだは `status`・`next`・結果のファイルを見に行かない。裏で回せないときは前で回す（それでも 1 回の呼び出しで済む）。
- run が `done` になると、進行役が `docs/pbi/HANDOFF.md` を書く。作業ルート・ブランチ・始めたときのコミット・目的・仕様・報告・run の状態の場所と、次にやること（報告を読む・差分を見る・PR を作る）だけの短い文にする。
- 呼び出し側は報告と引き継ぎ文を送り、「新しい会話（推奨）/ compact / このまま」を 1 問だけ聞く。新しい会話を選ぶと、ホストが新しいセッションを始められるなら引き継ぎ文だけを渡して始め、できないなら `/clear` のあとに引き継ぎ文を貼るよう頼む。モデルは自分で会話を消せない。
- まだ終わっていない run を新しい会話で続けるときは、`start` を飛ばして `drive` を呼ぶ（保留の手から始まる）。

## 本体の会話の応答の回数（変更前と変更後）

数えるのは、呼び出し側（本体）が 1 手のために返す応答の回数。

| 手 | 変更前 | 変更後 |
| --- | --- | --- |
| `check` | 3（コマンド・結果を書く・`done`） | 0（`drive` の中） |
| 外部の実行先の `launch` | 1（`run`） | 0（`drive` の中） |
| `prepare` | 2（写す・`done`） | 0（`drive` の中） |
| `agent` の `launch` | 2（起動・`done`） | 2（裏で起動・通知のあと `drive --done` を裏で） |
| `ask` | 2（見せる・`answer`） | 2（同じ）。答えのあとの手がモデルの要らない手なら `drive` を 1 回足す |
| `review_skill`・`omm_scan` | スキル＋`done` | スキル＋`drive --done` |
| 待つあいだの `status` | 何度でも | 0（通知を待つ） |

例: PBI 10 件・4 波・自動修正 1 回・直しの作業者 3 件・E2E 1 回（検査は 7 回）。

- 作業者を外部の実行先に回すテンプレート: 変更前はおよそ 50 回（検査 21・外部の起動 14・サブエージェント 6・質問 6・ほか）。変更後はおよそ 20 回（サブエージェント 6・質問 6・`drive` の起動 2〜3・見直しのスキル・報告と引き継ぎ）。
- 全部をサブエージェントに回す既定のテンプレート: 変更前はおよそ 65 回、変更後はおよそ 45 回。減るのは検査の分で、サブエージェントの起動の分は残る。

どちらでも、検査の出力は結果のファイルに残り、本体の会話には入らない。

## 会話が切れる場所

- 設計（仕様と状態の図の合意）のあと、実装の前: 設計の入口のスキルの受け持ち（このリポジトリの外）。引き継ぎ文に仕様・決定の記録・ブランチと、Atelier の引数を書く。
- run の `done` のあと、仕上げと PR の前: このリポジトリの受け持ち。`HANDOFF.md` を使う。

## Implementation Decisions

- `drive` は進行役の既存の手（`next`・`done`・`run`）をそのまま呼ぶ。守りの規則（G1〜G14）の検査と状態の遷移は変えない。
- `check` のコマンドは、作業ルートで 1 つずつ順に流し、最初に落ちたところで止める。終了コードを `exit_code` に、出力の末尾（8000 字まで）を `output` に書く。POSIX の書き方のコマンドを Windows で流すときは `--shell <POSIX シェル>` を渡す。時間切れは 124 にする。
- 無限に回らないよう、`--max-steps`（既定 200）で止める。途中で進行役が拒んだら、何手目で止まったかを添えてエラーを返す。
- `next`・`done`・`run` は 1 手ずつ進めたいときのために残す。

## Testing Decisions

合意済みの seam は進行役の CLI（`conductor.main`）。`tests/test_drive.py` で次を確かめる。

- 外部の実行先の起動と検査を済ませ、見直し役のサブエージェントの起動で止まる。
- 落ちた検査の終了コードと出力を結果のファイルに書き、質問で止まる。
- `--done` でサブエージェントの起動を閉じてから続ける。
- 呼び出し側の出番の手が保留なら、何もせずにそれを返す。
- `HANDOFF.md` にブランチ・始めたときのコミット・仕様・報告が載る。

## Out of Scope

- 設計の入口のスキル側の引き継ぎ（このリポジトリの外）。
- アーキテクチャ図（`assets/architecture.d2`）の描き直し。
- サブエージェントの起動そのものを本体の外に出すこと（深さ 1 で起こす決まりと合わない）。
