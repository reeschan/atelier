# PBI-001: role_results.py: 役割の受け渡しの JSON を確かめ、レビューを束ねる

- Model: (route.json)
- Depends on: none

## Goal
設計者・レビュー担当・テスト担当が JSON で結果を受け渡すための、3 つの schema の検査と、波のレビューを 1 つの束にまとめるスクリプトを作る。設計者は束の表だけを読み、照合が要る報告だけを開く。

## Targets
- 新規 `skills/atelier/role_results.py`: `check <files>` と `bundle --reports A,B --out F [--dir docs/pbi]`。関数 `check_review`・`check_test_result`・`check_episode`・`bundle`・`needs_designer`。schema 名の定数 `REVIEW`・`BUNDLE`・`TEST_RESULT`・`EPISODE`、`EPISODES`・`QUESTION_KINDS`。
- 新規 `skills/atelier/examples/roles/review.json`・`test-result.json`・`episode.json`: 各 schema の正しい例 (指示文から指す見本)。

## Do not touch
- 既存のスクリプトとテスト (`skills/atelier/*.py` のうち新規以外、`skills/atelier/test_*.py`)

## Acceptance criteria
1. 1 の終了コードが 0。
2. 2 が 3 ファイルとも `ok` を出し、終了コード 0。
3. 3 が `EX-1` の 1 行と `bundle:` の行を出し、終了コード 0。
4. 4 が終了コード 0 (bundle が欠けた EX-2 で終了コード 3 を返す)。
5. 5 が何も出さず終了コード 0。

## Verify commands
1. `python -m py_compile skills/atelier/role_results.py`
2. `python skills/atelier/role_results.py check skills/atelier/examples/roles/review.json skills/atelier/examples/roles/test-result.json skills/atelier/examples/roles/episode.json`
3. `python -c "import os,shutil;os.makedirs('docs/pbi/tmp/reviews',exist_ok=True);shutil.copy('skills/atelier/examples/roles/review.json','docs/pbi/tmp/reviews/EX-1.review.json')" && python skills/atelier/role_results.py bundle --reports EX-1 --out docs/pbi/tmp/b.json --dir docs/pbi/tmp`
4. `python skills/atelier/role_results.py bundle --reports EX-1,EX-2 --out docs/pbi/tmp/b2.json --dir docs/pbi/tmp; test $? -eq 3`
5. `python docs/pbi/tools/unchanged.py check PBI-1`
