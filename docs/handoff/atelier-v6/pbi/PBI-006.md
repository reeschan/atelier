# PBI-006: designer.md と appendix/episodes.md: 出番ごとの設計者の手順

- Model: (route.json)
- Depends on: PBI-002, PBI-005

## Goal
今の SKILL.md の本文 (設計者の手順) を、Atelier が持つ設計者の指示文 designer.md に移し、出番・問いの結果・レビューと テストの照合を足す。出番の契約 (JSON・つながり・起動のしかた) は付録 episodes.md にまとめる。

## Targets
- 新規 `skills/atelier/designer.md`: 今の `skills/atelier/SKILL.md` の frontmatter より下を元にする。見出し: Who you are (Atelier の設計者。付録の orchestrator はあなた。出番ごとに新しく起動される)、When to stop (5 つの止まる場所を「question の結果を書いて出番を終える」に。4 番目の波の境目の引き継ぎは消し、Kiln の handoff は status `handoff`)、Invariants (今のもの + 「検証と差分の精読はレビュー担当、テストの実行はテスト担当。あなたは束と test-result を照合する」)、Read on event (今の表 + 出番の契約は `appendix/episodes.md`)、Episodes (design・build・test・review・finish でそれぞれ何をして、どの next で終えるか)、Start・Run the stages・Approve (今の SKILL.md から。Approve は question kind `approve` で終える)、One PBI (作業者の起動 → レビュー担当 → 束 → 照合 → record_run)、Keep the context small、Working memory。
- 新規 `skills/atelier/appendix/episodes.md`: 役割の表 (呼び出し側・進行役・設計者・作業者・レビュー担当・テスト担当、それぞれの起動元・モデル・書くもの)、起動のしかた (agent・headless・inline と入れ子の深さ、`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`、Agent ツールが無いときの `error` reason `no-agent-tool`)、出番の結果 `atelier.episode/1` の項目、つながりの表、question の種類、`atelier.review/1`・`atelier.review-bundle/1`・`atelier.test-result/1` の項目 (例は `examples/roles/` を指す)、照合の決まり (束の表で照合が要る行だけ開く、verify の合否は `verify.py` の JSON、テストの cause は設計者が決める)、Kiln (境目で `agent_stats.py` の Context probe を流し、suggest・compact・handoff はどれも状態の板を書いて handoff で終える)。

## Notes
- 仕様: `docs/specs/atelier-v6.md` (このリポジトリの v6 の仕様)。用語は `skills/atelier/CONTEXT.md`。
- 指示文 (.md) は英語で書く。既存の付録の文体 (短い命令形、1 行 1 規則) に合わせる。スクリプトの docstring とコメントは日本語 (既存のスクリプトに合わせる)。
- テストは最後にまとめる (tests-at-end)。`skills/atelier/test_*.py` を作らない・変えない。
- 仕様の「設計者」「起動のしかた」「レビュー担当・テスト担当と JSON」「進行役」節が中身。進行役の CLI の出力の形は `skills/atelier/conductor.py` (PBI-002) の docstring を読む。
- designer.md は 200 行以内を目安に。手順の細部は付録に任せ、付録を指す (今の SKILL.md と同じ書き方)。毎出番の最初に読むので、短いほど安い。
- design の出番で AskUserQuestion を使っていた所 (設計するかの判断の「Otherwise」、ask-user のオプションの工程、lint の送信の許可) は、すべて question の結果 (kind `decision` か `send-approval`) にする。答えは次の起動の `Answer:` の行で来る。
- 承認: `appendix/adapters.md` の `## Confirm` の手順で `docs/pbi/notes/approve.md` と設計の正本を書き、`check: design-record` を付けた question kind `approve` で終える。`Answer:` が来たら、それは `check-reply` を通った返信。
- Kiln の線を測るコマンドは依頼文の `Context probe:` の行 (PBI-011 で `agent_stats.py --ctx --agent`・`--session` が入る)。
- 「Read on event」の表の `resume` の行は「呼び出し側の `conductor.py` が起動する。HANDOFF.md だけの v5 の run は inline」にする。
- inline (後ろ盾) のとき: 呼び出し側が designer.md に自分で従い、question の代わりにユーザーに直接聞き、`appendix/handoff.md` の引き継ぎを使う、と 2〜3 行で書く。
