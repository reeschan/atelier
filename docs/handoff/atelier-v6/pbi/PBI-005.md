# PBI-005: レビュー担当とテスト担当の依頼文

- Model: (route.json)
- Depends on: PBI-001, PBI-004

## Goal
レビュー担当が 1 報告の検証・受け入れ条件・差分を JSON に書き、テスト担当がテストの結果を JSON に書くための依頼文を用意する。設計者はこれを埋めて起動するだけになる。

## Targets
- `skills/atelier/prompts/pbi-review.md`: 全ての報告のレビューの依頼文に書き換える。subagent_type `atelier-reviewer`、description `PBI-<n>.review <短い文>` (rework は `<報告名>.review`)。手順: `verify.py PBI-<n> --name <報告名> [--skip-deferred]` を流す → `unchanged.py check PBI-<n>` → 受け入れ条件を 1 つずつ判定 → `git diff -- <targets>` を読む (deep は全体を、認証・権限・入力の検査・データの失い方・モジュールの契約に絞って) → `docs/pbi/reviews/<報告名>.review.json` (schema `atelier.review/1`) → `python <skill>/role_results.py check` が ok になるまで直す → 最後の返事は 1 行。
- 新規 `skills/atelier/prompts/tester.md`: subagent_type `atelier-tester`、description `TEST.<kind> <短い文>`。kind `wave` (`verify.py <報告名,...> --deferred` か、`tests-at-end.json` の `skill` を呼ぶ。失敗をファイル・テスト名・PBI・cause の案で書く)、`survey` (`appendix/tests-at-end.md` の下調べの表を `docs/pbi/notes/test-survey.md` に書き、数を JSON に)、`final` (全部の報告で最後の通し)。結果は `docs/pbi/verify/tests/<名前>.test-result.json` (schema `atelier.test-result/1`)。
- `skills/atelier/prompts/final-review.md`: subagent_type を `atelier-reviewer` にする (general-purpose から)。ほかは変えない。

## Do not touch
- `skills/atelier/prompts/design-review.md`・`kiln-chamber.md`・`lint-fallback.md`・`map-fallback.md`

2. 2 が 1 以上を出す。
3. 3 が 1 以上を出す。
4. 4 が何も出さず終了コード 0。

3. `grep -c "atelier.test-result/1" skills/atelier/prompts/tester.md`

## Notes
- 仕様: `docs/specs/atelier-v6.md` (このリポジトリの v6 の仕様)。用語は `skills/atelier/CONTEXT.md`。
- 指示文 (.md) は英語で書く。既存の付録の文体 (短い命令形、1 行 1 規則) に合わせる。スクリプトの docstring とコメントは日本語 (既存のスクリプトに合わせる)。
- テストは最後にまとめる (tests-at-end)。`skills/atelier/test_*.py` を作らない・変えない。
- 形は今の `prompts/*.md` (見出し 1 つ、何に使うかの 1 行、```text の依頼文、埋める括弧) に合わせる。依頼文に `prompts/kiln-chamber.md` の実装者のブロックを入れる行を残す。
- JSON の項目は `skills/atelier/role_results.py` と `skills/atelier/examples/roles/review.json`・`test-result.json` (PBI-001) に合わせる。依頼文の中に JSON の例を 1 つ (短く) 入れてよい。
- レビュー担当は作ったモデルで動かない: 依頼文の model は「opus、作った試行が opus なら sonnet で effort high」(今のまま)。
- verify の合否はレビュー担当の判断ではなく `verify.py` の終了コード。`verify.failed` は `docs/pbi/verify/<報告名>.json` の失敗の番号を写す。
- テスト担当の cause は案 (`intended`・`regression`・`unknown`)。決めるのは設計者と依頼文に書く。stash・reset で原因を探さない (今の付録の決まり)。
