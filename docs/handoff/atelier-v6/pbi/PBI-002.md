# PBI-002: conductor.py: 進行役の状態と start・next・done・answer・status

- Model: (route.json)
- Depends on: PBI-001

## Goal
呼び出し側が設計者の出番を 1 つずつ回すための進行役を作る。run の状態をディスクに持つので、呼び出し側は /clear と resume をせずに、何度でも next から続けられる。

## Targets
- 新規 `skills/atelier/conductor.py`: サブコマンド `start`・`next`・`done`・`answer`・`status` (各サブコマンドが `--dir`、既定 `docs/pbi` を受ける)。状態は `<dir>/conductor/run.json` (schema `atelier.run/1`)。`run` サブコマンドは PBI-003 で足すので、ここでは作らない。
- 新規 `skills/atelier/prompts/designer-episode.md`: `docs/pbi/notes/drafts/designer-episode.md` を元に、Goal の行を `Goal: {goal}` (goal.md のパス) にし、`Context probe: {ctx_probe}` の行を足す。

## Do not touch
- `skills/atelier/role_results.py` (import して `check_episode`・`EPISODES` を使うだけ)
- `skills/atelier/design_record.py` (サブプロセスで `check-reply` を呼ぶだけ)
- `docs/pbi/tools/conductor_smoke.py`

## Notes
- 仕様: `docs/specs/atelier-v6.md` (このリポジトリの v6 の仕様)。用語は `skills/atelier/CONTEXT.md`。
- 指示文 (.md) は英語で書く。既存の付録の文体 (短い命令形、1 行 1 規則) に合わせる。スクリプトの docstring とコメントは日本語 (既存のスクリプトに合わせる)。
- テストは最後にまとめる (tests-at-end)。`skills/atelier/test_*.py` を作らない・変えない。
- 契約は仕様の「進行役 (`conductor.py`)」節と、受け入れのスクリプト `docs/pbi/tools/conductor_smoke.py` (設計者が書いた。変えない)。食い違えばスクリプトに従う。
- 出力: 1 行目はいつも `state: <ready|running|question|finished|failed>`、全部で 8 行以内。`next` は `episode: <出番> seq <n>`・`launch: agent subagent_type=atelier-designer model=<m> description="ATELIER.<seq> <出番>"`・`prompt: <path>`・`result: <path>`・`then: python <skill>/conductor.py done` を出す。問いは `question: <kind> <path>` と `summary:` と `then: ... answer`。
- 終了コード: 0 進める・終わった / 10 答え待ち / 12 失敗 / 2 引数と状態の誤り (ロック・答える問いが無い・進行中の run がある start)。`start --force` は今の run.json を `run.<日時>.json` に退けて新しく始める。
- seq は起動 1 回ごとに 1 増える (同じ出番の再起動も)。running の間の `next` は同じ seq を出し直す。`done` は seq と出番が running と同じかを確かめる。
- つながりの表 (design→build、build→build|test|review|finish、test→build|review、review→build|finish、finish→終わり)。build は `next.wave` が要る。表に無い next・結果が無い・壊れた結果は失敗として数え、2 回続いたら kind `launch-failure` の問い。`handoff` は `state` のファイルが在れば同じ出番・同じ波を `Continue from:` 付きで起こせる状態にし、続けて 3 回目で kind `handoff-loop` の問い。どの答えでも数を 0 に戻す。
- `answer`: 答えを `<dir>/conductor/answers/<seq>-<kind>.md` に書く (`--reply F` は写す)。kind `approve` で `check` が `design-record` のときは `python <skill>/design_record.py check-reply --reply <その答え> --draft <question.path> --dir <dir>` を呼び、0 なら受ける、3・4・5 なら問いを残して `check-reply exit <code>` の行を出し 10。
- 依頼文: `prompts/designer-episode.md` の最初の ```text ブロックを読み `{name}` を埋める。`{?name}` で始まる行は値があるときだけ残す。値: work_root (cwd の絶対パス)、skill (このスクリプトのディレクトリの絶対パス)、episode、seq、wave、goal (`docs/pbi/conductor/goal.md`。`--dir` からの相対のまま)、workflow (無ければ `default`)、reviewer・tester (roles から)、continue_from、answer、result、ctx_probe (agent: `python <skill>/agent_stats.py --ctx --agent "ATELIER.<seq> "`、headless: `python <skill>/agent_stats.py --ctx --session <uuid>`。uuid は seq ごとに作り run.json に残す)。
- roles: home (`common.resolve_home(None)`) の `agents.json` の `roles`。既定は designer `{"model": "opus", "effort": null, "permission_mode": "auto"}`、reviewer `{"model": "opus", "effort": null, "when_built_on_opus": "sonnet high"}`、tester `{"model": "sonnet", "effort": null}`。不正な値は既定にして `warn roles.<role>.<key>: ...` の行を出す。
- ロック: 状態を変えるコマンドは `<dir>/conductor/lock` に pid を書いてから動き、終わりに消す。生きている pid なら `locked by pid <n>` で 2。pid が生きているかは `os.kill(pid, 0)` (Windows は `OSError` を死とみなしてよい)。`status` はロックを取らない。
- run.json の history: 起動ごとに `{seq, episode, wave, status, summary}` を足す (PBI-003 で cost_usd・session_id を足す)。書き込みは `common.write_json`。
