## 結論 {span=2}
```callout info この run で変わること
今は承認だけがページになり、ほかの問いはチャットの文で出ている。この run のあとは、どの問いも同じ入口からページで見せる。返事は、古いページへの返事でないかを確かめてから答えにする。5 つの作業に分け、3 回に分けて進める。
```

## 今の流れ
```flow
(設計者が問いを書く) -> {承認か}
{承認か} -> 呼び出し側がページを組み立てる: 承認
{承認か} -> チャットに文で出す: そのほか
呼び出し側がページを組み立てる -> 返事を確かめる
チャットに文で出す -> 返事をそのまま受ける
```

## この run のあとの流れ
```flow
- (設計者が問いを書く) -> {承認か}
- {承認か} -> 呼び出し側がページを組み立てる: 承認
- {承認か} -> チャットに文で出す: そのほか
+ (設計者が問いを書く) -> 1 つの入口で見せる (PBI-002)
+ 1 つの入口で見せる (PBI-002) -> {見せ方の設定 (PBI-001)}
+ {見せ方の設定 (PBI-001)} -> ページで見せる: html
+ {見せ方の設定 (PBI-001)} -> チャットに文で出す: md か off
- 呼び出し側がページを組み立てる -> 返事を確かめる
- チャットに文で出す -> 返事をそのまま受ける
+ ページで見せる -> どの返事も確かめる (PBI-003)
+ チャットに文で出す -> どの返事も確かめる (PBI-003)
```

手順書の書き直し (PBI-004・PBI-005) は、この流れを手順書に写す作業。流れそのものは変えない。

## 決めること {span=2}
```ask
PBI を作るモデルを、安いモデルから試す今の設定のままにしますか
* そのままにする | 費用が安い。合わないときは上のモデルに替わるので、そのぶん時間が延びることがある
- 初めから上のモデル (Sonnet) で作る | 費用は上がる。やり直しは減りやすい
```

```ask
スキル本体を新しい版に上げる作業を、この run の中でしますか
* run の外で自分で上げる | この run は作業用のコピーだけを変える。手元のスキルは変わらない
- run の終わりに設計者が上げる | 手元のスキルが書き換わる。その前にもう 1 度確認を出す
```

```ask
新しく足す入口が外のコマンドを呼ぶ所に、安全の点検をかけますか
* かけない | 見直しと試験だけで終える。外のコマンドに渡す値は固定で、利用者の入力を渡さない
- かける | 見直しのあとに、変えたコードだけを点検する。時間が少し延びる
```

## PBI {span=2}
| PBI | 何をするか | 終わると何ができるか | 先に要る PBI |
|---|---|---|---|
| PBI-001 | 見せ方の設定を html・md・off の 3 つにする | 設定 1 か所でページかチャットかを選べる | なし |
| PBI-002 | 問いを見せる入口を 1 本作る | どの問いも同じ手順でページになる | PBI-001 |
| PBI-003 | 承認以外の返事も確かめる | 古いページへの返事が答えにならない | PBI-002 |
| PBI-004 | 呼び出し側の手順書を、入口を使う形に書き直す | 呼び出し側がページを自分で組み立てない | PBI-002 |
| PBI-005 | 設計者の手順書に、見せ方の原則と問いの書き方を足す | 設計者がページ向けの問いを書ける | PBI-002 |

## 影響範囲 {span=2}
```flow LR
返事に付ける確かめの情報の計算 (PBI-002) -> *承認の返事の確かめ: 計算が変わると承認が通らない
返事を受ける処理 -> 返事に付ける確かめの情報の計算 (PBI-002): 名前を変えると読み込めない
呼び出し側の手順書 (PBI-004) -> *承認以外の返事の渡し方: 書き方が変わる
設計者の手順書 (PBI-005) -> 文書の中のパスの試験: 無いパスを書くと落ちる
```

- 承認の返事の確かめ: 計算を移すだけにし、今の承認の返事の試験をそのまま通す。
- 読み込み: 今の名前を残す。
- 承認以外の返事: 手順書に「返事はファイルにして渡す」と書く。
- 文書の中のパス: 書いたパスがあることを試験で確かめる。

見つけたが、この run ではしないこと:
- 承認以外の問いで、返事の渡し方のコマンドそのものを変えること (今のコマンドのまま、手順書で補う)。
