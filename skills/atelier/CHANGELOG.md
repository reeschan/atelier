## Unreleased

- Episode roles and the conductor (atelier v6 run, PBI-001 to 021): the caller (the session the user talks to) only runs `conductor.py` and passes its lines to the user; the conductor (`conductor.py`, a script with no model) keeps the run state in `docs/pbi/conductor/run.json` and decides each episode and its prompt; the designer (`agents/atelier-designer.md`) is launched fresh for every episode, and the worker, reviewer and tester run one level below it. Every episode ends with a result file (`atelier.episode/1`) at the path the prompt names; the reviewer and tester write `atelier.review/1` and `atelier.test-result/1`, and `role_results.py bundle` collects a wave's reviews and checks each verify JSON, `unchanged.py` and the built model itself. `agent_stats.py --ctx` reads a headless session (`--session`) and an agent description (`--agent`). The wave-boundary handoff is no longer a stop point: the four stop points stay approve, rework-limit, destructive and send-approval. Inline (neither nested agents nor `claude`) keeps the v5 flow, the caller following `designer.md` itself. Revision 2: `answer --approve --choices` approves for a caller that cannot write the envelope, and `answer --revise --text` asks for a change at the approval. While the run is running, `next` prints `state: running since` with no launch, and `next --relaunch` is for a caller that judges the episode stopped. Headless callers use `run --detach` and repeat `wait --timeout 300`. On Windows the lock's pid is checked with `ctypes` `OpenProcess` and `GetExitCodeProcess` (`os.kill(pid, 0)` sends Ctrl+C there). `handoff-loop` is judged by the progress in `docs/pbi/runs.jsonl` and `STATUS.md` (three handoffs in a row with neither changed). The designer writes `docs/pbi/waves.json`, and a re-entered build or test episode starts at the first unfinished step of `STATUS.md`, the reports, the reviews and `runs.jsonl` (a report without a review starts at the review). `is_error: true` in a headless reply is a launch failure whatever the `subtype` says. A subagent's reply may be empty: the file at the fixed path is the result. When an agent definition is not installed, `next` prints `warn agents:`, an agent launch uses `general-purpose` with the definition file to read, and headless adds `--agents`. See `appendix/episodes.md`. Final-review fixes: `start --force` stops the old runner and designer, `wait` and `status` print `stale: no live runner` with a `relaunch:` line, a rework build carries `Sent by:`, and role stats count only this run's `ATELIER.<run>.` agents.
- UI retouch: a new `when`, `ui-retouch`, for work that only fixes how existing screens look. It is one decision with `ui-change` (a new screen, flow or look) and both never hold in the same run, so a component that makes a new look (design-studio) and one that audits an existing look (unslop) never set two directions. The recommended example adds [unslop](https://github.com/heydamir/unslop) (CC BY 4.0) as `ui-design.unslop`: it stops at the direction, writes `docs/pbi/ui/<slug>/audit.md` (screens, numbered signs, verdict, direction, scope), and the plan builds the passes as PBIs whose acceptance criteria name the signs. See `appendix/optional.md`, `## UI retouch`.
- Confirm (PBI-012 to 014): Approve can be shown as HTML and approved by a pasted reply. `design_record.py` writes the record (`docs/pbi/design-record.json`, schema `atelier.design-record/1`: id, revision, targets, slice paths only) and the slices (`docs/pbi/notes/<id>.slice.json`), adds the `reply-meta-` envelope to the Approve Markdown, and checks a pasted reply against the record (last `am-reply-meta` fence at line start, `\r\n` as `\n`, quoted lines ignored; an unselected ask is no answer). `adapters.confirm` (`auto`, `off`, a skill name) picks the skill `answer-me-with-html` when it is installed and in the skill list, otherwise the same Markdown in chat; `adapter_gate.py` prints its row. `tools_check.py` lists the skill with its install line (repo answer-me-with-any at 8856dde51ff8) and installs nothing. See `appendix/adapters.md`, `## Confirm`.
- Map, lint survey and lint recheck: three optional stages in the bundled templates and the recommended example. `map` summarises the layers and modules in scope from an OMM cache kept outside the repository (`omm_cache.py`), an `omm-scan` run, or `prompts/map-fallback.md`. `lint-survey` ranks the range with jevlint before the design; `lint-recheck` compares the merge-base with the working tree after the test stage and before review (`lint_run.py`, `lint_compare.py`). They pick their first usable row and end with a fallback prompt (`flow.PICK_FIRST`). See `appendix/map.md` and `appendix/lint.md`.
- Send approval: jevlint sends file contents to an outside model only in those two stages, and only after the user says yes to the dry-run numbers right before each send (the fifth stop point). `lint_run.py --mode model` refuses without an unused approval for the same file list. Secret files and the files of sensitive PBIs stay AST only. Workers never run jevlint.
- Tests at the end is on by default (`appendix/tests-at-end.md`): workers change code only, deferred checks run once per wave, a test stage after the last wave fixes, rewrites, deletes and adds tests. `{"enabled": false}` in `docs/pbi/tests-at-end.json` turns it off; with no test command it says off in STATUS.md.
- Kiln is on by default and reaches every subagent and external worker (`prompts/kiln-chamber.md`). A worker that will not finish under its peak writes `## State` and reports `NEEDS_CONTEXT` with `Open: kiln`; a new worker continues. Lines: designer 120000/180000, implementer 60000/90000. `kiln_log.py` writes the compact-event line and keeps the run id (`--run-id` on resume).
- Recommended tools: `tools_check.py` lists oh-my-mermaid, jevlint, sac-strategic-compact and pstack's test principle with install commands and fallbacks; Approve and setup show the missing ones, and the run goes on with the fallback when the user does not install them. `agents.json` `tools.<name>.path` points at a tool outside PATH.
- appendix/memory.md, appendix/handoff.md: the resume search passes `include_workspaces: true`, and finish writes a done memory that supersedes the latest handoff (shared-memory ADR 0003).
- Kiln docs: when Kiln is on and `docs/pbi/kiln.json` is absent, thresholds come from the enabled workflow template; copying the sample overrides them. Setup keeps an existing `kiln.json` unless the user approves a replace. Handoff stores `Run id:` and resume restores it. While Kiln is on, measure at stage boundaries as well as wave boundaries.
- Kiln (窯): optional context-capacity constraint. Off unless `docs/pbi/kiln.json` exists or the workflow template sets `kiln.enabled`. See `appendix/kiln.md` and the sample `examples/kiln.json`. Bundled templates (`workflows/jev-routed.json`, `workflows/high-model.json`, `examples/workflows/recommended.json`) carry a `kiln` stub with `prompt_install` that offers [sac-strategic-compact](https://github.com/reeschan/sac-strategic-compact). The stub does not turn kiln on and does not install the skill.
- README.md and README.ja.md: Highlights describe optional Kiln and link `appendix/kiln.md` and sac-strategic-compact.
