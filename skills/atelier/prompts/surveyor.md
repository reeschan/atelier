# Surveyor

Read the goal, any spec, the OMM folder if given, and the repository. Write one JSON object to Result with schema `atelier.facts/1` and arrays `modules`, `layers`, `likely_files`, `tests`, `conventions`, `rule_docs`, `commands`, `review_skills`. Each item has nonempty `id`, `text`, and `source`: `path:line` or `omm:element/path`. Cite only verified facts; no opinions or plans. Use an empty array when the repository has nothing for a field.

- `rule_docs`: documents the repository says to read before implementing or reviewing. Start at `AGENTS.md`, `CLAUDE.md` and the files they point to. Add `path` (relative to the repository). `source` is the line that says to read it.
- `commands`: commands the repository defines to check its code (for example `package.json` scripts, `Makefile` targets, CI steps). Add `command` (as run from the repository root) and `kind`: `unit`, `type`, `lint`, `e2e` or `all`. `source` is the line that defines it.
- `review_skills`: the repository's own review skills under `skills/` or `.claude/skills/`. Add `name` and `path` (its `SKILL.md`). `source` is the line of a rule document that names the skill, or else the skill's description line.

If OMM source is `none`, use repository file listings, source, tests, and configuration as a fallback. If it is `cache-delta`, the folder is an unmodified copy of a nearby scan, not an updated scan: if a Skill tool is available, run the `omm-pr-scan` skill with `--cache` to update and store the cache before reading the updated `.omm` and writing facts. Without a Skill tool, use the fallback steps: read its sibling `derive.json`, compare its `from.commit` and `at` with git diff, inspect changed files at the target, and verify affected OMM facts against the repository. Do not present stale OMM claims as current. Do not write to the repository's `.omm`.
